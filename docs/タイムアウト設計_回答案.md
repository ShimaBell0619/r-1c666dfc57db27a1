# タイムアウト設計に関する回答

前提：**ブラウザー → Front Door → Web Apps → APIM → Functions Premium** の同期HTTP通信です。以下は公式仕様と設定案の整理であり、現在の実設定値は未確認です。

## 1. 各レイヤーのタイムアウト

- **Front Door（Standard/Premium）**：オリジン応答タイムアウトは **16～240秒**で変更可能です。今回は240秒を想定します。既定値はサービス制限資料で60秒ですが、一部の公式資料には30秒の記載もあるため、実設定を確認します。  
  公式：https://learn.microsoft.com/ja-jp/azure/azure-resource-manager/management/azure-subscription-service-limits  
  公式：https://learn.microsoft.com/ja-jp/troubleshoot/azure/front-door/troubleshoot-issues

- **Web Apps**：HTTP応答の制限は **Windows約230秒／Linux約240秒**で、変更できません。  
  公式：https://learn.microsoft.com/ja-jp/troubleshoot/azure/app-service/web-request-times-out-app-service

- **APIM**：バックエンドの応答ヘッダー待機は **既定300秒**です。`forward-request`で変更可能ですが、**240秒超の動作は保証されません**。  
  公式：https://learn.microsoft.com/ja-jp/azure/api-management/forward-request-policy

- **Functions Premium**：関数の実行時間は既定30分で、上限なしにも設定できます。ただし、**HTTPトリガーの応答は230秒以内**です。  
  公式：https://learn.microsoft.com/ja-jp/azure/azure-functions/functions-scale

- **ブラウザー → Front Door**：Front Doorにはヘッダー受信5秒、Keep-Alive 90秒の制限がありますが、**業務処理全体の待機時間とは別**です。画面側のタイムアウトはアプリ実装に依存します。  
  公式：https://learn.microsoft.com/ja-jp/azure/azure-resource-manager/management/azure-subscription-service-limits

## 2. リクエスト全体の制限時間

今回の同期処理では、**FunctionsのHTTP応答制限である230秒が主要な上限**です。ただし通信・処理のオーバーヘッドや、各HTTPクライアントの設定によって、それより早くタイムアウトします。例えばC#の`HttpClient`は既定100秒です。  
公式：https://learn.microsoft.com/ja-jp/azure/azure-functions/functions-bindings-http-webhook-trigger  
公式：https://learn.microsoft.com/ja-jp/dotnet/api/system.net.http.httpclient.timeout?view=net-10.0

## 3. アプリケーション側の推奨設定

基盤の制限に達する前にエラーを返せるよう、**内側から外側へ余裕を持たせる**方針を推奨します。仮に長時間処理を許容するなら、次の値が一例です。

- APIM → Functions：**180秒**
- Web Apps → APIM：**190秒**（HTTPクライアント側で明示設定）
- ブラウザー側：**200秒程度**
- Front Door：**240秒**

※上記は**Microsoftの推奨値ではなく設計例**です。実際は業務処理の所要時間に合わせて、より短い値も検討します。  
公式：https://learn.microsoft.com/ja-jp/azure/api-management/forward-request-policy  
公式：https://learn.microsoft.com/ja-jp/dotnet/api/system.net.http.httpclient.timeout?view=net-10.0

## 4. タイムアウト時の挙動・注意点

HTTP応答がタイムアウトしても、**Functionsの処理が継続する場合があります**。再試行によりデータ更新が二重実行されないよう、処理の冪等性などを考慮する必要があります。  
公式：https://learn.microsoft.com/ja-jp/azure/azure-functions/functions-bindings-http-webhook-trigger

**補足**：230秒を超える業務処理が必要になった場合に限り、Durable Functionsなどを用いた**非同期処理**を検討します。今回は通常の同期HTTP処理を前提とします。  
公式：https://learn.microsoft.com/ja-jp/azure/durable-task/durable-functions/durable-functions-http-features
